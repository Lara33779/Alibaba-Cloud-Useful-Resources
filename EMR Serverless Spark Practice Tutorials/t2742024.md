Use EMR Serverless Spark to connect to an external Hive Metastore {#ddf5ae70f6jpi}
==================================================================================

E-MapReduce (EMR) Serverless Spark allows you to connect to an external Hive Metastore. This way, you can access the data that is stored in the Hive Metastore with ease. This topic describes how to configure settings in EMR Serverless Spark to connect to an external Hive Metastore to implement efficient management and utilization of data resources in a work environment. {#4f1c443ac9tiq}

**Prerequisites** {#7eb747cd3dt3r}
----------------------------------

A workspace and an SQL compute are created. For more information, see [Create a workspace](t2488607.md#){#099d760a3d06e} and [Manage SQL sessions](t2699789.md#){#28418cba9ank8}.

**Limits** {#3d554e32d1252}
---------------------------

* You can only preview the Hive Metastore service. To use the Hive Metastore service, join the DingTalk group (ID: **58570004119** ) that provides technical support for EMR Serverless Spark customers.

  {#335febe5ea519}
{#94a19f4fd0oxv}
* To use the Hive Metastore service, you must restart the existing compute service in your workspace.

  {#a3138abc684u9}
{#dcdbc1129dumr}
* After you specify a Hive Metastore as a default catalog, your workflow tasks automatically depend on the Hive Metastore.

  {#a93d3ffadfvk1}
{#31e2c8399b6yx}

{#162162425c6uj}

**Procedure** {#fdd6d1b1e03p7}
------------------------------

### Step 1: Prepare the Hive Metastore service {#f0818536fb9cl}

**Note**

In this example, the Hive Metastore that is deployed in EMR on ECS is used as an external service. If a Hive Metastore has been deployed in your virtual private cloud (VPC), skip this step.

1. On the EMR on ECS page, create a DataLake cluster that contains the Hive service and for which the **Metadata** parameter is set to **Built-in MySQL** . For more information, see [Create a cluster](t2136630.md#){#22faaae4f79xs}.

   {#d6b3421c2f1eb}
{#7a614923f3lbu}
2. Log on to the master node of the DataLake cluster in SSH mode. For more information, see [Log on to a cluster](t2139059.md#){#8cb1918b2dkug}.

   {#a7bd67e8d8ij8}
{#355490e3b4upd}
3. Run the following command to open the Hive CLI: {#17e2d3ba881fr}

   ```bash
   hive
   ```

   {#0e362551ebe15}{#16e1c9b037kuz}
{#16e1c9b037kuz}
4. Run the following commands to create a table named dw_users that points to Object Storage Service (OSS) and write data to the table: {#ad7f016dfburo}

   ```sql
   CREATE TABLE `dw_users`(
     `name` string)
   LOCATION
     'oss://<yourBucket>/path/to/file';
   
   INSERT INTO dw_users select 'Bob';
   ```

   {#c7b7e4c9b63dr}{#84015c0a11vln}
{#84015c0a11vln}

### **Step 3:** Enable the port of the Hive Metastore {#afac70291286i}

   You can log on to the [VPC console](https://vpcnext.console.aliyun.com/vpc)[VPC console](https://partners-intl.aliyun.com/login-required#/vpc) and obtain the CIDR block of a desired vSwitch on the **vSwitch** page. {#de16db3d55een}

   ![image](../images/p794226.png)
   {#c9b220f9dfsyp}
{#14d89a33b677f}
2. Configure security group rules. {#dac7de4840tfz}

   1. Log on to the [EMR console](https://emr-next.console.aliyun.com/#/region/cn-hangzhou/resource/all/ecs/list ""){#ed1a19e279ust}.

      {#5b797987a9oi6}
   
   2. On the **EMR on ECS** page, find the desired cluster and click the name of the cluster in the Cluster ID/Name column.

      {#f7b7af6f62mzp}
   
   3. In the Security section of the **Basic Information** tab, click the link to the right of **Cluster Security Group** .

      {#b05fed0d26c0l}
   
   4. On the **Security Group Details** tab, click **Add Rule** , configure the **Port Range** and **Authorization Object** parameters, and then click **Save** . {#b975b6796edvj}

      {#dfcf4208939sb}{#153166ebdd8c8}

      |--------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
      | **Parameter**            | **Description**                                                                                                                                                                                                                |
      | **Port Range**           | The port number. Enter 9083.                                                                                                                                                                                                   |
      | **Authorization Object** | The CIDR block of the vSwitch obtained in the previous step. {#03ce70e689mku} **Important** To prevent attacks from external users, we recommend that you do not set the **Authorization Object** parameter to **0.0.0.0/0** . |

### **Step 4: Connect to the Hive Metastore** {#5fe73f684em9o}

1. In the left-side navigation pane of the **EMR Serverless Spark** page, click **Catalog** .

   {#d59369a3e83ci}
{#f82fcab915w7m}
2. On the **Catalog** page, click **Add Catalog** .

   {#05fac27c036y5}
{#2450cbe3c2dlt}
3. In the Add Catalog dialog box, click **External Hive Metastore** and configure parameters. The following table describes the parameters. {#b37c7200fepb0}

   ![image](../images/p821435.png){#469222da42pkz}
   {#f2337df48eowk}{#47f125bed4oen}{#da65530cc62vn}

   |-------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | **Parameter**                 | **Description**                                                                                                                                                                                                                                                                                                                                                                                                                          |
   | **Network Connection**        | The network connection that you created in Step 2.                                                                                                                                                                                                                                                                                                                                                                                       |
   | **Metastore service address** | The Uniform Resource Identifier (URI) of the Hive metastore. Configure this parameter in the `thrift://<IP address of a Hive Metastore>:9083` format. {#71f25b26fbtsu} `<IP address of a Hive Metastore>` specifies the internal IP address of the Hive Metastore. In this example, the internal IP address of the master node of the EMR cluster is used. You can view the internal IP address on the **Nodes** tab of the EMR cluster. |

   {#f7acc2f447d93}{#c4e40ae94561v}
{#c4e40ae94561v}

**FAQ** {#fa0e4045be476}
------------------------

**How do I access HDFS data?** {#d8e838b00ch62}

The method that you can use to access HDFS data varies based on whether your HDFS cluster is a high-availability (HA) cluster. {#0d749369a3c7j}

* Non-HA HDFS cluster{#c2b89813854mo}

  The `location` of a table points to an HDFS path of a non-HA HDFS cluster, and only one NameNode is used to manage the namespaces of HDFS file systems. In this case, you can directly access HDFS data.
  {#7e6ce2e6a9wea}
{#0a3d665bc85s1}
* HA HDFS cluster{#767e6a7d455r7}

  The `location` of a table points to an HDFS path of an HA HDFS cluster, and the HDFS cluster has multiple NameNodes. In this case, you must add the required configurations for the desired compute in the **Spark Configuration** section. Then, you can use Java Runtime or the Fusion engine to access HDFS data as expected. {#bd9135d7288lh}

  Use Java Runtime to access HDFS data {#724484561bytf}
  -----------------------------------------------------

  Find the desired cluster and click **Services** in the Actions column. On the Service tab, find HDFS and click Configure. On the **Configure** tab of the HDFS service page, configure the required configuration items on the **hdfs-site.xml** tab based on the following sample code. {#bb7b67f0224pc}
  **Note**
  * When you search for a configuration item by name, you must remove `spark.hadoop.` before the name of the configuration item.

    {#46cc0c6386trw}
  {#c49a07420f7qn}
  * The values of the configuration items in the following code are for reference only. You can view the values of the configurations items in the EMR console.

    {#1bf2c704e31j4}
  {#1d964941c7ah8}

  {#ae40e811d7vua}

  ```xml
  spark.hadoop.dfs.namenode.rpc-address.hdfs-cluster.nn1  master-1-1.<cluster-id>.<region>.emr.aliyuncs.com:***
  spark.hadoop.dfs.nameservices                       hdfs-cluster
  spark.hadoop.dfs.ha.namenodes.hdfs-cluster          nn1,nn2,nn3
  spark.hadoop.dfs.client.failover.proxy.provider.hdfs-cluster  org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider
  ```

  {#ddc09dce00fue}
